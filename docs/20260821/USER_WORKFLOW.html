Trace every step a person (or a demo) actually walks

Three end-to-end traces plus one unattended trip — each followed User Action → Razor component → Minimal API endpoint → Handler → External service → Table Storage, with the file that owns each link. Generated 2026-08-21.

TIER 1Executive summary (30 s)

Four traces are documented end-to-end:

  1. Sign-in (BFF) — Microsoft or guest, sets a single encrypted cookie, returns 401-JSON if unauthenticated.
  2. Standard duel (Remote vs Remote) — Pick → Compare → 202 → Arena subscribes SignalR → tokens stream → verdict → ELO moves.
  3. Browser-model duel (WebLLM) — Same UI up to the Arena; inference runs in the tab, finished HTML POSTed back.
  4. Unattended demo (10 duels) — DemoPlanner resolves the schedule, each duel enters the ordinary POST /api/duels, judge auto-decides.

Every write path that moves ELO goes through RecordVerdictHandler. Every persisted result goes through DuelResultRepository. Two contracts hold the design together: a human decision always wins the race against the auto-judge; ELO never moves on no evidence.

Implementation reference

TIER 3Step-by-step with concrete file references

Trace A · Sign-in (BFF) — expanded

  1. Click "Sign in" in NavMenu.razor (calls NavigationManager.NavigateTo("/login")).
  2. Login.razor renders two buttons: one targets /auth/login/microsoft, one (Development only) targets /auth/login/fake.
  3. Auth/BffAuthentication.cs → MapAuthEndpoints maps the routes. /auth/me is always anonymous so the SPA can read auth state without 401s.
  4. OIDC code flow for Microsoft: AddOpenIdConnect uses PKCE, authority https://login.microsoftonline.com/common/v2.0, callback /signin-oidc. Allowed tenants default to "any well-formed Entra issuer" unless AzureAd:AllowedTenants is populated.
  5. Cookie session — PoLocalCompare.Session is HttpOnly, SameSite=Strict, Secure, sliding 8 h. The cookie event handler returns 401 JSON (never 302) for API calls so the WASM client can render the Login page properly.
  6. Dev fake — /auth/login/fake only exists outside Production; FakeAuthHandler throws when constructed in Production.

Trace B · Standard duel — expanded

  1. Home.razor (.po-btn Compare click) → PoLocalCompare.Client.Services.HttpClient.PostAsJsonAsync("/api/duels", request).
  2. DuelsEndpoints.MapDuelsEndpoints wires the group; the POST / handler calls CommenceDuelHandler.HandleAsync which writes the duel row (with Verdict=Pending, snapshot names).
  3. DuelExecutionService.EnqueueAsync queues a background work item (long-lived), keyed on DuelId; the handler returns 202 Accepted + Location header.
  4. BackgroundTaskService dequeues and invokes DuelExecutionService.RunAsync; it resolves an IRemoteInferenceProxy via GetRequiredKeyedService<> based on ModelType.
  5. Remote path: FoundryInferenceProxy.StreamAsync opens an SSE connection (chat/completions?stream=true); each token batch raises ModelStatusUpdate(duelId, side, …) over DuelHub. SandboxedViewport.ShouldRender + RenderCoalescer.Request() keep the WASM tab responsive (~16 ms trailing edge).
  6. Local path: instead of a server call, DuelExecutionService emits StartLocalInference(left|right) over DuelHub. Arena.razor → LocalInferenceDriver invokes the WebLLM worker. The finished HTML is POST /api/duels/{id}/local-result (always anonymous) → DuelResultRepository.SaveAsync.
  7. Result enrichment — DuelResultEnricher.Enrich stamps OutputQualityScore, EnergyWh, EnergyCostUsd, ApiCostUsd from the model & result.
  8. Verdict collection — Arena.razor shows vote buttons while a vote can still land. On click → POST /api/duels/{id}/verdict → RecordVerdictHandler.HandleWithRetryAsync (one 412 retry on ETag contention).
  9. The gate — RecordVerdictHandler: once-only per duel; refuses a verdict when both results are failures (GuardAgainstNoEvidenceAsync); stamps VerdictSource; runs EloCalculator.Update (K=32, expected-score formula) and writes two EloHistory rows (one per side). After every write it invalidates CacheTags.Leaderboard.
  10. Notifiers — LobbyNotifier publishes LobbyEvent(verdict) on the lobby group. DuelHub.Clients.Group(duelId).VerdictRecorded(...) paints the arena panel.

Trace C · Browser-model duel — expanded

  1. Arena receives OnStartLocalInference(side, modelId); LocalInferenceDriver runs the WebLLM web-worker (cache-busted as webllm-worker.js?v=N).
  2. The worker loads weights (locally vendored under wwwroot/models/, else CDN), generates HTML, and posts back the result + token count + timings.
  3. Arena.razor posts LocalResultRequest to POST /api/duels/{id}/local-result. The handler normalises via HtmlOutputNormalizer.Normalize, enriches, and saves.
  4. When both sides complete, Arena.razor swaps from streaming UI to vote UI (otherwise a pending AutoJudge.RunAsync is the only way forward).

Failure shape: a worker-side abort sets IsFailure=true, FailureReason=...; the DuelResult row is stored as a failure. AutoJudge treats a one-sided failure as a walkover, both-sided as Pending — see Trace D step 4.

Trace D · Unattended demo — expanded

  1. Demo.razor mounts and calls GET /api/duels/demo-plan?rounds=10.
  2. DemoPlanHandler delegates to Shared/Demo/DemoPlanner — a pure seeded planner that returns the schedule; pairings flip left/right per round to neutralise judge position bias.
  3. On Start, the page loops with POST /api/duels setting autoJudgeDelaySeconds: 0 (clamped 0–3600). Demos are real duels: they persist, get judged, and they move ELO.
  4. DuelExecutionService finishes inference; AutoJudge.RunAsync(0) schedules itself. After the streamed output, the judge queries Duel: if non-Pending, it stands down; if both results are failures, it stands down; if one side failed, it records a walkover verdict via RecordVerdictHandler with VerdictSource=Ai; else it calls FoundryDuelJudge.JudgeAsync.
  5. FoundryDuelJudge calls Foundry chat completion with a json_schema response ({winner: A|B|Tie, reason}). It assigns the two outputs to slots A/B by coin flip, retries on 429 with Retry-After up to RateLimitRetryMax times.
