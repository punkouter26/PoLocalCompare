TIER 1Executive summary (30 s)

PoLocalCompare is a single .NET host that hosts a Blazor WASM client and exposes minimal-API endpoints under /api/* plus a SignalR hub at /hubs/duel. The dashboard below arranges the whole system in three layers: components (how the code is sliced), pipelines (how requests travel), and entities (what is persisted). Narrative cards on the right explain each piece in plain English.

Architecture is VSA — each Features/<Slice> folder is a flat vertical slice with its endpoints, handlers, entities and repository. Common/ holds the genuinely cross-slice code (background queue, inference proxies, telemetry, cache tag plan, Key Vault bootstrap, persistence abstractions). Shared/ carries only DTOs, enums, IDs and pure logic — no DI, no I/O.

Narrative cards — plain English for each slice

TIER 3Each card pairs a real-world summary with the slice that owns it

slice

Duels

The engine room. Owns a duel's full lifecycle — from the POST /api/duels write to the RecordVerdict ELO update. Wires up DuelExecutionService (background queue), DuelHub (SignalR live events), LobbyNotifier (global ticker), AutoJudge and FoundryDuelJudge.

  • Features/Duels/DuelsEndpoints.cs — Minimal API surface.
  • Features/Duels/Duel.cs — aggregate root (incl. snapshot names).
  • Features/Duels/RecordVerdictHandler.cs — the single ELO gate.
  • Features/Duels/EloCalculator.cs — K=32 expected-score formula.
slice

Models

Catalog of everything that can compete. Read-only at runtime — the seeder writes the default list once and is idempotent; OrphanModelIdRemapper rewrites duel history to the current catalog on startup so retired IDs don't leave dead rows.

  • Features/Models/Model.cs — record (incl. CurrentElo denormalized).
  • Features/Models/ModelSeeder.cs — 21 seeded models (7 browser · 2 Ollama · 12 remote), pricing from the list rates.
  • Features/Models/ModelVisibility.cs — hides Ollama in Production.
  • Features/Models/OrphanModelIdRemapper.cs — insert-then-delete remap.
slice

Leaderboard

The fair ranking. Reads Models + EloHistory (sparkline) and either DuelResult (avg cost) and projects LeaderboardEntryDto (with a real WinRate). Fronted by HybridCache — tag-invalidated on every verdict write.

  • Features/Leaderboard/GetLeaderboardHandler.cs — sort by Elo / Quality / Cost / Value.
  • Features/Leaderboard/GetKillListHandler.cs — per-opponent aggregates.
  • Features/Leaderboard/WinRateCalculator.cs — divide-by-zero guard.
slice

Archive

Lab-report export. ExportLabReportHandler reads the duel, calls HtmlLabReportRenderer, and serves the result as a self-contained HTML file with a Content-Disposition: attachment header.

  • Features/Archive/ArchiveEndpoints.cs — single route under /api/duels/{id}/report.
  • Features/Archive/HtmlLabReportRenderer.cs — pure HTML builder.
slice

Ollama

Local daemon interop (Development only). Three tiny handlers: GET /gpu-status, GET /available-models, POST /benchmark. The whole slice is hidden by ModelVisibility.Filter outside Development, so the Production catalog has no dead entries.

  • Features/Ollama/OllamaEndpoints.cs — 3 routes.
  • Features/Ollama/OllamaContracts.cs — request/response DTOs.
slice

Diagnostics

Liveness & smoke. /health is the JSON probe (compose of registered IHealthChecks); /api/diag/smoke is the same picture for the diag tab; /diag is the Razor view that renders it without leaking secrets.

  • Features/Diagnostics/HealthEndpoints.cs — route map.
  • Features/Diagnostics/HealthChecks.cs — health check implementations.
cross-cut

Auth · BFF

The WASM client never sees a token. The server owns the OIDC code flow, stores an encrypted HttpOnly cookie, and routes login through /auth/login/microsoft (PKCE, well-formed-Entra-issuer validation) and /auth/login/fake in Development. FakeAuthHandler throws when constructed in Production as defense in depth.

  • Auth/BffAuthentication.cs — registration + MapAuthEndpoints.
  • Single policy: RequireAuthenticatedUser over Cookie OR Fake.
cross-cut

Common/Background

Reliable work for duels. IBackgroundTaskQueue is a singleton; BackgroundTaskService is a hosted consumer. Nothing else resolves the concrete queue — the rest of the app just enqueues.

  • Common/Background/IBackgroundTaskQueue.cs
  • Common/Background/BackgroundTaskQueue.cs
  • Common/Background/BackgroundTaskService.cs
cross-cut

Common/Inference

Strategy — one proxy per remote model type. FoundryChatRequest knows two body shapes (reasoning vs classic chat) and which deployments accept the stream_options extension. SSE is read by SseChatStreamReader.cs; tokens are counted by HtmlStreamCounters.cs.

  • Common/Inference/FoundryInferenceProxy.cs
  • Common/Inference/OllamaInferenceProxy.cs
  • Common/Inference/IRemoteInferenceProxy.cs
  • Common/Inference/InferenceTelemetry.cs — OTEL source name.
cross-cut

Common/Caching

One tag, one plan: CacheTags.Leaderboard is invalidated by RecordVerdictHandler after every verdict write. Fronted reads: leaderboard:{sortBy}.

  • Common/Caching/CacheTags.cs

Common/KeyVault · Persistence · Telemetry

The plumbing. Key Vault prefix is PoLocalCompare--; persistence is Azure.Data.Tables with 409-swallowing creates and ETag-conditional updates; telemetry is InferenceTelemetry as both Activity source and Meter for OTEL.

  • Common/KeyVault/*
  • Common/Persistence/*
  • Common/Telemetry/InferenceTelemetry.cs

PoLocalCompare.Client

Blazor WASM, served by the API at /. Thin Razor over Shared/ helpers. Services/ holds what genuinely needs the browser: LocalInferenceDriver, the SignalR client, JS interop. Pages/: Home, Arena, Leaderboard, Archive, Demo, Login, NotFound.

PoLocalCompare.Shared

DTOs, enums, strongly-typed IDs and the pure helpers that all three other projects need: Analysis/LineDiff.cs, Analysis/OutputAnalysis.cs, Prompts/PromptLibrary.cs, Demo/DemoPlanner.cs, Presentation/ view-models + enums.

Step-by-step narratives

1 · A user starts a duel

A person signs in (cookie set), picks two models on Home.razor, types a prompt, and clicks Compare. The WASM client serializes the three fields and calls POST /api/duels. The server writes a Duel row with status Pending and snapshot display names, then enqueues a background work item and returns 202 with a Location header. Within ~30 ms the user is on Arena.razor.

2 · Inference runs (three paths)

The background item fans out. For each side, the execution service resolves the right IRemoteInferenceProxy by ModelType: Remote opens an SSE chat completion to Azure AI Foundry; LocalService (Dev) talks to Ollama on localhost:11434; Local (browser) emits StartLocalInference over SignalR and waits for the WASM web-worker to POST its result back. Every token batch updates a DuelResult row and pushes a ModelStatusUpdate over the hub.

3 · Verdict collection & ELO write

Either the user clicks a button (human verdict) or AutoJudge steps in after AiJudge:DelaySeconds. Either way, RecordVerdictHandler is the only path that writes the verdict. It enforces three rules: no second verdict (409), no verdict when both sides failed, and a precise VerdictSource so an LLM judge can be filtered out of an LLM-vs-human re-ranking afterwards. Then EloCalculator (K=32) computes deltas, two EloHistory rows are appended, and the leaderboard HybridCache tag is invalidated.
