Authorization in three sentences

There is exactly one rule: you are signed in, or you are not. Every API route requires a session unless it explicitly says otherwise, and nothing anywhere checks a role, a scope or an owner.

Signing in accepts any Microsoft account. In Development you can also click "Continue as Guest", and tests authenticate with a header — both paths are removed in Production, and the header handler throws if it is ever constructed there.

The one endpoint that stays open everywhere is the callback the browser's WebGPU worker uses to hand back its finished output, because that worker has no credential to send.

Headline findings

✅ The posture itself is correct. options.FallbackPolicy = options.DefaultPolicy makes every endpoint require an authenticated user by construction. Auditing therefore reduces to auditing the opt-outs — there is no way to add an unprotected endpoint by forgetting something.
⚠️ One unauthenticated write reaches Production. POST /api/duels/{duelId}/local-result is .AllowAnonymous() unconditionally. Anyone who knows a duel id can submit that side's HTML output while the duel is still running.
⚠️ Two Development-only endpoints are destructive and unauthenticated. POST /api/dev/reset wipes Duels, DuelResults and EloHistory and resets every model to 1200 ELO. The IsDevelopment() mapping guard is the only thing protecting it — and a developer's localhost writes to whatever storage account is configured.
ℹ️ Roles are decoration. A Guest role is issued and X-Fake-Roles is honoured; /auth/me returns them. No RequireRole, no named policy, no [Authorize(Roles=…)] exists anywhere. Likewise Duel.OwnerId and Duel.VerdictBy are recorded but never compared — any signed-in user can judge any duel.

Defence-in-depth notes

What is genuinely well guarded

  • FallbackPolicy means a new endpoint is protected by omission, not by remembering.
  • FakeAuthHandler throws in its constructor if the environment is Production — misconfiguration fails loudly at startup rather than opening a door.
  • Cookie is HttpOnly + SameSite=Strict + SecurePolicy=Always, 8-hour sliding. The WASM client never holds a token.
  • OnRedirectToLogin is rewritten to a bare 401, so an API caller never receives an HTML login page.
  • returnUrl is sanitised to local relative paths only — //evil.com is rejected, closing the open-redirect.
  • Hub methods only subscribe; every server→client push goes through IHubContext, so no authenticated client can inject into another duel's feed.
  • Issuer validation is shape-checked against ^https://login.microsoftonline.com/{guid}/v2.0$, or an explicit tenant allow-list when AzureAd:AllowedTenants is populated.
  • Judge inputs are delimiter-fenced with a per-call random hex marker and the system prompt names them untrusted data — a prompt-injection countermeasure in the one place model output re-enters a model.

Client-side gating is not a control

_Imports.razor applies @attribute [Authorize] to every routed page and App.razor renders Login.razor for the unauthenticated. This is a UX affordance only — it runs in the user's browser. BffAuthenticationStateProvider reads GET /auth/me, and the server remains the sole authority.

The client also hides the guest button outside non-Production, mirroring the server's !IsProduction() gate on /auth/login/fake. Both gates exist; only the server one matters.
